    Implement the following functions in `agent_core/publishing/oauth.py`. Replace the existing `NotImplementedError` stubs.

    **Imports (follow existing codebase conventions — stdlib, blank line, third-party):**
    ```python
    import json
    from pathlib import Path

    import google.auth.transport.requests
    from google.oauth2.credentials import Credentials
    from googleapiclient.discovery import build
    ```

    **Constants (module-level):**
    ```python
    SCOPES = [
        "https://www.googleapis.com/auth/youtube",
        "https://www.googleapis.com/auth/youtube.upload",
        "https://www.googleapis.com/auth/yt-analytics.readonly",
    ]
    TOKEN_FILENAME = "yt-oauth-token.json"
    ```

    **Private helper — `_project_root() -> Path`:**
    - Resolves `Path(__file__).resolve().parent.parent.parent` (agent_core/publishing/oauth.py → agent_core → project root)
    - This is a function (not a constant) so it works even if the module is imported from different working directories

    **Private helper — `_token_path(channel: str) -> Path`:**
    - Returns `_project_root() / "channels" / channel / TOKEN_FILENAME`
    - Validates the parent directory (`channels/{channel}`) exists; if not, raises `FileNotFoundError` with message:
      `f"Channel directory not found: {channels_dir}. Run /viral:onboard or create channels/{channel}/ first."` (per D-11 error messaging)

    **Private helper — `_load_token_data(channel: str) -> dict`:**
    - Calls `_token_path(channel)` to get path
    - Reads and parses JSON from the token file
    - If file doesn't exist, raises `FileNotFoundError` with message:
      `f"OAuth token not found at {path}. Run: python scripts/setup-yt-oauth.py --channel {channel}"` (per D-11)
    - Returns the parsed dict

    **Public — `save_initial_token(channel: str, credentials: Credentials) -> Path`:**
    - Serializes credentials to the standard dict format used across all scripts:
      ```python
      token_data = {
          "token": credentials.token,
          "refresh_token": credentials.refresh_token,
          "token_uri": credentials.token_uri,
          "client_id": credentials.client_id,
          "client_secret": credentials.client_secret,
          "scopes": list(credentials.scopes),
      }
      ```
    - Ensures the channel directory exists (`_token_path(channel).parent.mkdir(parents=True, exist_ok=True)`)
    - Writes JSON with `indent=2` via `Path.write_text()`
    - Returns the `Path` to the saved token file
    - Purpose: Called by the CLI script after the OAuth browser flow completes (D-02)

    **Public — `get_or_refresh_credentials(channel: str) -> Credentials`:**
    - Calls `_load_token_data(channel)` to get token dict
    - Builds `Credentials` object:
      ```python
      creds = Credentials(
          token=data["token"],
          refresh_token=data["refresh_token"],
          token_uri=data["token_uri"],
          client_id=data["client_id"],
          client_secret=data["client_secret"],
          scopes=data["scopes"],
      )
      ```
    - If `creds.expired` and `creds.refresh_token`:
      - Calls `creds.refresh(google.auth.transport.requests.Request())` (per D-08)
      - Persists the refreshed credentials back to disk via `save_initial_token(channel, creds)`
    - If `creds.expired` but no `refresh_token`:
      - Prints warning: `f"WARNING: Token for {channel} has no refresh_token. Re-run: python scripts/setup-yt-oauth.py --channel {channel}"` (per D-11)
    - Returns `creds`
    - NOTE: `used` scope check is intentionally omitted — scopes are set at OAuth consent time and don't change between refresh cycles. The token's scopes reflect what the user originally consented to.

    **Public — `get_authenticated_service(channel: str) -> Resource`:**
    - Calls `get_or_refresh_credentials(channel)` to get valid credentials
    - Per D-08: passes credentials to `build("youtube", "v3", credentials=creds, static_discovery=False)`
    - `static_discovery=False` avoids the default `static_discovery=True` which requires a local discovery doc;
      setting it to `False` fetches the discovery doc from the API, which is the correct behavior for
      desktop/server apps. Do NOT omit this parameter — without it, `build()` raises
      `UnknownApiNameOrVersion` errors in environments without cached discovery docs.
    - Returns the built Resource (google-api-python-client handles auto-refresh on 401 per D-08)

    **Public — `refresh_token_if_expired(channel: str) -> bool`:**
    - Calls `_load_token_data(channel)` (raises FileNotFoundError if missing — caller should handle by directing user to re-auth)
    - Builds `Credentials` object (same as `get_or_refresh_credentials`)
    - If `creds.expired` and `creds.refresh_token`:
      - Refreshes via `creds.refresh(google.auth.transport.requests.Request())`
      - Persists via `save_initial_token(channel, creds)`
      - Returns `True` (token was refreshed)
    - If `creds.expired` but no `refresh_token`:
      - Prints actionable warning per D-11
      - Returns `False`
    - If not expired:
      - Returns `True` (token is already valid — no refresh needed)

    **NOTES:**
    - Do NOT add `__all__` — the module docstring and function visibility serve as the contract.
    - Keep the existing module-level docstring but extend it to describe all four public functions.
    - Use `#` inline comments for section markers (e.g., `# ====== PUBLIC API ======`) per CONVENTIONS.md.
    - All functions must have Google-style docstrings with `Args:`, `Returns:`, `Raises:` sections.
    - Per D-12: no silent failures — always log/print context for errors.
    - Per D-11: all error messages must include the exact next command the user should run.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | I (Information Disclosure) | Token file `channels/{Name}/yt-oauth-token.json` | accept | Token file contains refresh_token + client_secret. Existing project uses 0600 perms for credentials via Phase 2 Fernet encryption (SEC-03), but OAuth token files are plain JSON per D-10. Accept risk — token file sits under `channels/` which is gitignored, and the refresh_token expires if revoked. Future work: encrypt OAuth tokens using the same Fernet mechanism from SEC-03. |
| T-05-02 | S (Spoofing) | `save_initial_token()` input | accept | Credentials object comes from google-auth-oauthlib's `run_local_server()` — the library validates the OAuth response. The core module trusts the provided credentials object. |
| T-05-03 | E (Elevation of Privilege) | `get_or_refresh_credentials()` token loading | mitigate | Token file path is constrained to `channels/{channel}/yt-oauth-token.json` — channel name is a simple string with no path traversal risk since it's joined via `Path / channel / filename`. |
</threat_model>
