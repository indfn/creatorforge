<objective>
Implement cross-channel insights aggregation functions in `agent_core/analytics/insights.py`.

**Purpose:** After analytics data is collected by Plan 07-01 (collector.py) and stored as dated JSONL per video, this plan provides the read-side aggregation layer. It compiles metrics across all videos in a channel, computes per-metric summary statistics (mean, median, min, max, count), identifies top/bottom performing content, and produces cross-channel comparisons so the system can detect which channels and content strategies are working best.

**Output:** Fully implemented `insights.py` with `aggregate_channel()` and `aggregate_all()`.
</objective>

       - `_project_root() -> Path` — resolves project root as `Path(__file__).resolve().parent.parent.parent`
       - `_validate_channel(channel: str) -> None` — same regex as uploader.py: `^[A-Za-z0-9_-]+$`, raises ValueError on invalid chars (path traversal protection)
       - `_channel_analytics_dir(channel: str) -> Path` — calls `_validate_channel`, returns `_project_root() / "channels" / channel / "data" / "analytics"`
       - `_read_jsonl_entries(path: Path) -> list[dict]` — reads a JSONL file, yields parsed dicts per line (skips empty lines, logs warnings on JSON parse errors). Does NOT use `validate_or_raise` on every entry (too heavy for bulk read — defensive parse is sufficient; entries were validated on write per D-11).

    3. **`_compute_metric_stats(values: list[float | int]) -> dict`** (private helper):
       - Takes a list of numeric values for one metric across all videos/entries
       - Returns dict: `{"mean": float, "median": float, "min": float, "max": float, "count": int}`
       - Returns `{"mean": 0.0, "median": 0.0, "min": 0.0, "max": 0.0, "count": 0}` for empty list
       - Uses `statistics.mean` and `statistics.median` from stdlib

    4. **`_identify_performers(entries: list[tuple[str, dict]], metric: str, top_n: int = 3) -> list[dict]`** (private helper):
       - Takes a list of `(video_id, entry_dict)` tuples and extracts `entry["metrics"][metric]`
       - Filters out entries where the metric is missing or None
       - Returns top N entries sorted descending by metric value
       - Each result dict: `{"video_id": str, "metric": str, "value": float}`
       - Use a single shared function with a `reverse=True/False` parameter to get both top and bottom

    5. **`aggregate_channel(channel: str) -> dict`** (main function — per D-14):
       - Validates channel name via `_validate_channel`
       - Resolves analytics dir via `_channel_analytics_dir`
       - If directory doesn't exist → log warning and return empty-aggregation dict (graceful, not crash)
       - Discovers all JSONL files with: `analytics_dir.glob("*/**/*.jsonl")` — catches all video_id dirs
       - For each JSONL file, calls `_read_jsonl_entries` to get dicts
       - Collects all entries with their video_ids (extracted from parent directory name)
       - Builds a combined list of `(video_id, entry)` tuples
       - **Numeric metrics to aggregate** (all numeric fields from the schema's `metrics` object):
         - `views`, `impressions`, `likes`, `comments`, `shares`, `saves`, `subscribers_gained`
         - `ctr`, `retention_30s`, `avg_view_duration`, `avg_view_percentage`, `completion_rate`, `engagement_rate`
       - For each metric, collects all values (latest entry per video wins — deduplicate by video_id keeping the last-occurring entry to avoid double-counting the same video), then calls `_compute_metric_stats`
       - **Top/bottom 3 performers** — calls `_identify_performers` (and its reverse) for the three ranking metrics: `views`, `ctr`, `engagement_rate`
       - Returns dict:
         ```python
         {
             "channel": channel_name,
             "total_videos": int,           # unique video count
             "total_entries": int,           # total JSONL lines across all files
             "metrics": {
                 "views": {"mean": ..., "median": ..., "min": ..., "max": ..., "count": ...},
                 "ctr": {...},
                 # ... all numeric metrics
             },
             "top_performers": [
                 {"metric": "views", "rankings": [{"video_id": "...", "value": 1000}, ...]},
                 {"metric": "ctr", "rankings": [...]},
                 {"metric": "engagement_rate", "rankings": [...]}
             ],
             "bottom_performers": [
                 {"metric": "views", "rankings": [{"video_id": "...", "value": 10}, ...]},
                 # ...
             ]
         }
         ```

    **Implementation constraints:**
    - NO external dependencies beyond stdlib (`statistics` module only, not numpy — numpy is NOT a project dependency per pyproject.toml)
    - NO I/O inside the critical path (read all files first, then compute)
    - Graceful degradation: malformed JSONL lines are logged and skipped, missing directories return empty aggregation
    - Follow the same `_safe_` pattern from aggregator.py for handling missing/None values
    - Use `_project_root()` pattern consistent with other `agent_core/` modules
    - Log at INFO level: "Aggregated N entries across M videos for channel {channel}"
    - Log at WARNING level: skipped malformed lines, missing directories
