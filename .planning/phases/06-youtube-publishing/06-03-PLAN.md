### `assign_to_playlist(channel, video_id, playlist_id) -> bool`
- Calls `youtube.playlistItems().insert(part="snippet", body={"snippet": {"playlistId": playlist_id, "resourceId": {"kind": "youtube#video", "videoId": video_id}}})` then `execute()`.
- On success: log "Assigned video {video_id} to playlist {playlist_id}" → return True.
- On `HttpError(404, ...)`: log `WARNING` "Playlist {playlist_id} not found — skip assignment. Create it with --ensure-playlist." → return False (do NOT crash — per D-09).
- On `HttpError(403, "quotaExceeded")`: log `ERROR` "Quota exhausted. Cannot assign to playlist." → return False.
- Before calling the API, read `channel_config.json` → extract `channel_config.get("playlists", [])` → if the `playlists` list has an entry whose `id` matches `playlist_id`, also log `INFO` "Assigning to playlist '{entry.name}' ({playlist_id})".
- The playlist_id lookup is a **warning-only** check: if the playlist_id doesn't match any entry in channel_config.json, log a WARNING that it wasn't found in config but still attempt the API call (the ID might be valid but not in config yet).

### `create_playlist(channel, name, description="", privacy="public") -> str`
- Calls `youtube.playlists().insert(part="snippet,status", body={"snippet": {"title": name, "description": description}, "status": {"privacyStatus": privacy}})`, then `execute()`.
- Returns the new playlist ID (`result["id"]`).
- On `HttpError`: log error, reraise.
- Also returns the playlist ID as a string.

### `pin_comment(channel, video_id, text) -> str`
- Calls `youtube.commentThreads().insert(part="snippet", body={"snippet": {"videoId": video_id, "topLevelComment": {"snippet": {"textOriginal": text}}}})`, then `execute()`.
- YouTube API does NOT support programmatic pinning of comment threads. After creating the comment:
  1. Log `INFO` "Comment created on video {video_id} (id: {comment_id})"
  2. Log `WARNING` "YouTube API does not support programmatic comment pinning. To pin this comment, go to YouTube Studio > Videos > {video_id} > Comments, find this comment, and click the pin icon."
  3. Print the manual instructions to stdout so the user sees them clearly.
- Returns the comment thread ID (`result["id"]`).
- On `HttpError(403, "commentsDisabled")`: log ERROR "Comments are disabled for video {video_id}. Enable comments in metadata and retry." → reraise.

### `update_metadata(video_id, title=None, description=None, tags=None, category_id=None) -> bool`
- Performs a READ-MODIFY-WRITE pattern to preserve unset fields:
  1. Calls `youtube.videos().list(part="snippet", id=video_id).execute()` to get current snippet.
  2. Extracts `current = response["items"][0]["snippet"]`.
  3. Builds update body: `{"id": video_id, "snippet": {}}` and copies fields from `current` for any parameter that is `None`.
  4. For non-None params: use the new value. Tags must be a list (convert comma-separated string to list via split if needed).
  5. Calls `youtube.videos().update(part="snippet", body=updated_body).execute()`.
- Return True on success, False on HttpError (log error).
- **Chapter markers (PUBLISH-11):** If `description` contains timestamp lines formatted as `HH:MM:SS - Title` or `MM:SS - Title`, they become YouTube chapter markers. The function does NOT generate chapters itself — it accepts the description as-is, so the caller (or metadata module) should pre-append chapter markers to the description before calling this function. Log INFO with count of chapter lines detected in the new description.

### `update_thumbnail(channel, video_id, thumbnail_path) -> bool`
- Resolves `thumbnail_path` relative to project root.
- Validates file exists and is an image (check `.jpg`, `.jpeg`, `.png` extension — log WARNING and return False if not).
- Uses `youtube.thumbnails().set(videoId=video_id, media_body=str(thumbnail_path)).execute()`.
- **NOTE:** This duplicates `upload_thumbnail` from the upload flow (plan 06-01). Include a comment: `# TODO: Deduplicate with uploader.upload_thumbnail — post_publish uses same MediaFileUpload pattern`.
- Return True on success, False on error (log ERROR).

### Argument parser setup
```python
def main():
    parser = argparse.ArgumentParser(description="Post-publish YouTube actions")
    parser.add_argument("--channel", default="ChannelA", help="Channel name")
    parser.add_argument("--video-id", required=True, help="YouTube video ID")
```
Note: `--channel` defaults to "ChannelA" but is NOT required (allows omitting for single-channel setups).

### Operation flags (mutually exclusive — only one operation per invocation)

| Flag | Type | Action |
|------|------|--------|
| `--pin-comment` | str | Call `pin_comment(channel, video_id, text)` + print manual pinning instructions |
| `--assign-playlist` | str | Call `assign_to_playlist(channel, video_id, playlist_id)` + print success/failure |
| `--ensure-playlist` | str | Call `create_playlist(channel, name=value)` → get new ID → call `assign_to_playlist(...)` on the new ID |
| `--update-title` | str | Call `update_metadata(video_id, title=value)` |
| `--update-description` | str | Call `update_metadata(video_id, description=value)` |
| `--update-tags` | str | Call `update_metadata(video_id, tags=value.split(","))` — split comma-separated string into list |
| `--update-thumbnail` | str | Call `update_thumbnail(channel, video_id, path)` |

**Multiple `--update-*` flags can be combined in one call** (e.g., `--update-title "New Title" --update-description "New desc"` makes a single `update_metadata` call). `--pin-comment`, `--assign-playlist`, and `--ensure-playlist` are standalone and if combined with update flags, process both (no mutual exclusivity enforcement beyond documented behavior).

### Error handling in CLI
- Each operation catches its own errors independently
- If an operation fails (returns False or raises), log the error and continue to next operation (if multiple flags provided)
- Use `print("...")` for user-facing output (stdout), `logging.error(...)` for internal diagnostics

### Exit codes
- 0: All requested operations succeeded
- 1: Any operation failed

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args → YouTube API | User-provided video IDs, playlist IDs, and comment text cross into API calls |
| File system → YouTube API | Thumbnail file path from CLI arg is read and uploaded |
| Config file → application | `channels/{name}/channel_config.json` contains playlist IDs and YouTube settings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Spoofing | `assign_to_playlist` / `create_playlist` | mitigate | Channel identity enforced by OAuth — `get_authenticated_service(channel)` loads the channel's own token; an attacker would need the channel's OAuth token file |
| T-06-03-02 | Tampering | `update_thumbnail` file path | mitigate | Validate `thumbnail_path` exists and has a `.jpg/.jpeg/.png` extension before passing to API; reject non-image paths |
| T-06-03-03 | Information Disclosure | All functions (via logging) | mitigate | Log video IDs and playlist IDs at INFO level (acceptable for agent CLI), do NOT log OAuth tokens or channel config secrets |
| T-06-03-04 | Denial of Service | All API calls | mitigate | Wrap every `execute()` call in try/except for `HttpError(403, "quotaExceeded")` — log and return False, do not crash |
| T-06-03-05 | Spoofing | `--channel` CLI arg | accept | CLI runs locally with project access; channel name must match a real `channels/{name}/` directory; OAuth token per-channel prevents cross-channel access |
</threat_model>
